## Decisions made

**`ADR-0084` — the prove-usefulness phase.** The original hypothesis is
demonstrated: a repository can be compiled into a Canonical Knowledge Model that
answers engineering questions. **Success is now measured by the quality of the
questions Engineering OS can answer about real software systems**, not by the
sophistication of the metamodel.

**`ADR-0085` — work begins with questions, not entities.** *What engineering
question cannot yet be answered?* — never *we need another entity*. The order is
the decision, and "only if necessary" sits third deliberately.

**`ADR-0086` — the query engine is the semantic API.** Every question is a
declared query. The engine holds **operators**; questions are **data**.

**`ADR-0087` — model one large external software system.** Not a toy, not another
Engineering OS repository. The success criterion is **not** *can it represent the
system* but *does it reveal relationships existing documentation cannot?*

## What was learned

### Declaring questions produced questions the code form had not

Nine hand-written functions became eleven declared queries. **`Q-unaccepted`
(*which revisions are not Active?*) and `Q-orphan-concepts` (*which Concepts does
nothing reference?*) did not exist before the file did.**

This is the third time a declarative table has generated content its imperative
form did not — after `validation-rules.md` produced `VR-0005`–`VR-0007` and
`registries.md` produced the `membership` question. **The pattern is now
reliable enough to plan around: writing a list invites completeness in a way
writing a function does not.**

### Two useful questions need no traversal

`Q-unenforced` and `Q-orphan-concepts` are `select` plus `reject` — no graph walk
at all. Evidence that the valuable questions are not all about reachability,
which is what a traversal-only engine would have assumed.

### The equivalence check was built because a debt was recorded

`ADR-0086` accepted two engines and recorded the cost honestly: *two engines can
diverge and nothing detects it.* Writing that sentence made the detector obvious,
and it exists in the same session.

**It found a real defect immediately.** Rewriting the Explorer's query block
deleted three helper functions — `esc`, `link`, `pill` — and the page still
looked plausible. The cross-check failed with `esc is not defined` before any
human would have opened it.

### An expectation was wrong and the model was right

`tests/projects/acceptance` declared `Q-impact(Actor.Reviewer)` as empty. It is
not: changing the reviewer affects the acceptance record that names them.

**Pinning query answers in fixtures catches author error, not just regression.**
The same effect as `VR-0007` and as `relationship-taxonomy`'s missing semantic
category — three times now, declared expectations have corrected the author.

### The phase change makes "wait" the default

`ADR-0062` made building the default, and that was right while the architecture
was unproven. `ADR-0084` inverts it. The honest consequence, recorded in that
ADR: **most of the existing repository does not obviously pass its own new
metric** — the ontology, the graph views and much of the governance corpus answer
no engineering question about a real system.
