**`ADR-0114` — a drift report is a work queue, not a document.** Every drift
class declares `routes-to` and `routing-rationale`. A class that routes nowhere
must say why, in the registry, next to the class.

domain's engineering knowledge. **A domain skill is not a parser plugin.** It

would be evidence the domain does not fit (`ADR-0085`).

experience of an engineering team using Engineering OS on a real Brownfield

## What was learned

### Routing a report exposed classes nobody had thought about

Eleven classes became fifteen **while writing the routes, not while reviewing the
taxonomy.** The question *which plan handles this?* is answerable only if the
class describes something a person would act on, and four gaps surfaced the
moment the column existed.

This is the fifth time a declarative table has generated content its prose form
did not — after `validation-rules.md`, `registries.md`, `queries.md` and
`plans.md`. **The pattern is now something to reach for deliberately.**

### The first plan that can destroy curated knowledge begins by not destroying it

`P-review-unsupported` handles the one drift class where the correct outcome may
be **removing something a human authorized**. It begins with `locate` — find the
evidence — because the drift item asserts only that *a rerun did not produce
this*, which is equally consistent with the rerun being wrong. **The system found
exactly this case in `SESSION-0043` and the rerun was the one at fault.**

### A phase borrows steps, not applicability — and said nothing when they missed

`P-review-unsupported` was run against `Invariant.Addbusinessminutes` and two of
its three phases produced **nothing at all**, silently.

The cause is structural: **a plan phase borrows a recommendation's steps, and
each step's query declares its own `applies-to`.** `Q-assumptions` accepts
`Artifact`; the subject was an `Invariant`. The step was skipped and the phase
rendered as empty, indistinguishable from *there was nothing to do*.

Those are opposite meanings. The planner now reports the difference:

```text
── ASSESS: Determine which of the three causes applies   requires: locate
     ! review skipped: applies to Artifact; Invariant.Addbusinessminutes is a Invariant
       [Q-assumptions]
```

`tools/check-plans.py` now finds the condition at authoring time, per subject
type — which is the granularity at which it hid. Asking *does this phase work for
the plan?* answers yes. Asking *does it work for an Invariant?* answers no, and
that is the question a team asks.

**One hollow phase across eight plans**, reported and not failed: a plan serving
four subject types legitimately has steps that suit some of them.

### The defect and the drift report are the same family

`C1`/`R4` disagreeing about multi-`describe` suites was found because two
mechanisms were compared. This was found because a plan was **actually run**
rather than validated.

Both were invisible to every check that existed, and both became visible the
moment something downstream consumed the output. **Consumption is a stronger
test than validation**, and the repository now has two independent instances of
it.

### Three governance records had unparseable front matter for many sessions

`ISSUE-0038`, `ISSUE-0050` and `ISSUE-0061` all open their title with a quotation
mark — *"authoritative" names both a lifecycle state and an artifact kind* — which
YAML reads as a quoted scalar followed by garbage. **All three failed to parse,
and had failed since the day they were written.**

Every governance check consumes front matter, so all three were **silently
skipped by every check that has ever run**: no id, no status, no supersession.
The one defect that hides the others.

The cause is not the quoting. **It is that the governance validation lived as a
script retyped from memory at the end of each session** — never committed, never
identical twice, and therefore never able to fail the same way twice.

It is now `tools/check-governance.py`, in the suite, over **271 records**. This
is the same correction the project has already made four times — rules, queries,
recommendations, plans — applied at last to the check that guards the corpus
those decisions live in.

### The new admission test was applied immediately, to this session

Domain Discovery Skills were declared in `ADR-0115` as a category. Building seven
of them would have been architecture. **One, with a real domain and questions a
consultant would actually ask, is what a team would notice.** The remaining six
were deferred by `ADR-0116` on the session that wrote it.
