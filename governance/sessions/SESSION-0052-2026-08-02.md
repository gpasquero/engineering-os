## What was learned

### Writing down what a stranger would type found four defects

None was found by any architectural session, and none would have been.

**`discovery/run.py` crashed on any project directory outside this checkout.**
It called `path.relative_to(ROOT)` on an output path — fine for every internal
run in fifty-one sessions, and **broken for every third-party use**, since a
stranger's project directory is not inside our repository.

**`tools/direct.py` crashed on `I-investigate`**, a workflow documented in the
README, with `KeyError: 'kpi'`. The registry deliberately declares that intent
as having **no plan** — a recorded gap, stated as such in its own file — and the
tool had no branch for the case its own data models. It now reports the gap and
points at the recommendation that does apply.

**Nothing could be onboarded out of the box.** The journey's most important
workflow required a repository on one of two supported stacks. A bundled demo
now makes it followable with nothing external.

**The README described "milestone M1 of 11" and stated that no skills, policies
or contracts had been built.** Fifty-one sessions of work were invisible to
anyone arriving at the repository.

### The smoke test failed on its first three runs, which is the point

It found the missing stack profile, then the out-of-tree crash, then a curation
tool that raised before it could refuse. **Each failure was a real blocker for a
real user**, and each was invisible to a suite where 17 fixtures, 20 registries
and 315 governance records were all passing.

`tools/test.py` verifies that the product is correct. **`tools/smoke.py` verifies
that it can be used**, and until this session nothing did.

### The onboarding bridge needed no vendor integration at all

`ADR-0140` specified a non-deterministic skill run by Claude or Codex. The
smallest implementation that makes it real turns out to need **no SDK, no API
key and no network call**: `brief` writes the contract and the evidence
boundary, the user runs the worker in the tool they already have, and `ingest`
validates what comes back.

The validation gate is where the architecture lives, and it rejects on first
contact: a numeric confidence, a source outside the Mechanical Model, a case
that argues only *for*, a stale digest. **The worker cannot write knowledge
because there is no path by which it could.**

### The honest README is the harder deliverable

Its status section separates *implemented* from *experimental* from
*unvalidated* from *planned*, and says that the onboarding skill has never run
end to end with a frontier model, that guidance correctness is unmeasured, and
that no human has ever completed a curation session.

**A README that oversold this would fail the only test that now matters.** The
first stranger to try it would find out in ten minutes, and would then trust
nothing else in it.

### Thirteen of fourteen, and the fourteenth governs

Every checklist item verifiable from inside is done. **The last one — *a
third-party engineer completes the flow without private guidance* — cannot be
satisfied from inside**, and it is the only external oracle this project will
ever have had.
