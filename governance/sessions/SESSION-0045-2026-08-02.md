## What was learned

### The most valuable thing found was our own fabrication

`R4` proposes a general Invariant from a test suite's declared subject. **No
`wa-b2b` suite declares one** — JUnit has no `describe` block and this repository
does not use `@DisplayName`.

`R4` fell back to the **file name**, and proposed 67 invariants of this shape:

```
Invariant.AgentServiceTest     "AgentServiceTest"
Invariant.AuditDeciderTest     "AuditDeciderTest"
```

**Thirteen per cent of the proposal set asserted nothing**, carried full
provenance and `S-inferred` support, and was indistinguishable to a reviewer from
a real finding.

**`ai-desk` could not have exposed this.** All 69 of its suites declare a
`describe` block, so the branch never executed in fourteen milestones. **A single
repository had validated a rule and hidden a defect in the same act.**

> **A fallback that supplies an identifier where a statement is missing does not
> improve coverage. It manufactures evidence.**

The fix is verifiably not an optimization for Java: **`ai-desk` still produces
exactly 299 proposals.** That number is the whole argument — a correctness fix is
a no-op on the repository that validated the rule.

### The noise was load-bearing, and removing it made the model worse

`Q-constraints` now answers nothing, because the fabricated general invariants
were **the only thing emitting `constrains` edges** from an Invariant to the
Capability it guards.

**13 % fabricated content was purchasing one real relationship.** The honest
model is a *less connected* model, and that is the correct trade — but it is the
first time this project has made a change that measurably reduced what the
product can answer, and it should not be recorded as a clean win.

### Two of seventeen questions matter most and both return nothing

`Q-rationale` — *which decision established this?* — answers **0 of 216**. The
repository has **135 markdown documents and zero the profile recognises as a
decision record.** The knowledge is there; the model cannot see it.

Nothing at all is known about **authorization**, in a multi-tenant B2B product
with `@PreAuthorize`, JWT and OIDC. **143 routes, and not one carries who may
call it.**

**453 proposals, and the two questions a new engineer asks on day one — *why is
it like this* and *who is allowed to do what* — are both unanswerable.** The
count is not the result. That gap is.

### The metamodel needed nothing

Twenty-three entities absorbed a Java Spring application on the first attempt
with **zero additions**. A JPA entity is a `Concept`; a feature package is a
`Capability`; a controller is an `Artifact` that `implements`.

**Every gap is a gap in observation, not in representation** — which is the
strongest evidence yet for `ADR-0085`, and the answer to question 7: the
shortfalls are ours, not the repository's.

### The same five entities, twice

`ai-desk` exercised six of twenty-three; `wa-b2b` exercises five. Two stacks, two
domains, the same five. Under `ADR-0119`'s own rule this is now **repeated
evidence** — and it points at the interpreter, not at either repository. Nothing
in the six deterministic rules can propose an `Actor` or a `Policy` whatever it
is pointed at.

### Applying a lifecycle to the wrong directory silently merged two models

Verifying the `ai-desk` lifecycle, it was run against
`external/ai-desk-onboarding` — a different project directory, from an earlier
session, that already held an Authoritative Engineering Model.

**It succeeded.** It reported `maintained model 83 sources` and a drift report
with categories that had never appeared before, and nothing anywhere said the
two models were unrelated.

`apply()` writes authorized proposals into `<project>/model` and **never asks
whose model is already there**. Reverted with `git clean`; recorded as debt
rather than fixed, because the remedy — a project identity that application
checks — is a design question and not a typo.

**A team would make this mistake more easily than we did**, and the failure is
silent, which makes it worse than a crash.

Re-run against the correct directory, the lifecycle reproduces its recorded
result exactly: 299 → 72 authorized → 4 incremental → 76 maintained → 302 fresh
→ drift `123 / 10 / 104 / 1`. **The only diff in four artifacts is the mechanical
digest**, which changed because the vocabulary version did (`ADR-0110`), while
every proposal and every drift item is byte-identical.

### Applying the discipline was harder than writing it

The benchmark produced a list of things that did not work, and every item looked
like a task. **Four candidate Discovery Skills were named and none was built**,
including the one that is plainly the most valuable — `DS-authorization-discovery`.

`ADR-0119` was written before the run, which is the only reason it held.
