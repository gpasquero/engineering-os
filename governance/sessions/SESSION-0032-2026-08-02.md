## What was learned

### The cross-source finding

> **A `managedFields` entry's `time` is not the time that entry last changed.**

The `ManagedFieldsEntry.Time` doc comment says the timestamp does **not** update
when a field is removed because another manager took it over. The documentation
says `force` **removes the field from all other managers' entries**. Neither
mentions the other, and `conflict.go`'s `printManager` renders that timestamp in
the message a user reads while reasoning about ownership.

**No fetched document contains the conclusion.** This is what `ADR-0087` set out
to test.

**And it is the weakest form of the claim that still counts.** A documentation
and observability finding, not a correctness bug. A contradiction between sources
would have been materially stronger; this validation did not find one, and 41
nodes is far too small to conclude none exists.

### The metamodel generalized with one correction

It was designed against a governance repository. It mapped an API-machinery
subsystem — KEPs to `ADR`, docs and source and tests to `Artifact`, guarantees to
`Invariant` — and needed **one** change, which was not about Kubernetes.

**The failed requirement was provenance**: *every assertion must preserve
provenance to its exact source*, and no authoring field could carry a URI. The
correction is an `attributes` mapping the compiler gives **no meaning**. Its two
regression fixtures mention no Kubernetes.

That the gap was in *authoring representation* rather than in the metamodel is
the more interesting half. **Twenty-three entities were sufficient; the file
format was not.**

### Fetching the sources was the decision that made the milestone real

Authoring from memory would have produced a plausible model, correct-looking
KEP numbers and confident file paths — **and it would have proven nothing**,
because the finding would have been about my recall rather than about the
sources.

Every URL was fetched, every path HTTP-checked, every test name extracted by
grep. Where a source was *not* read in full — KEP-2885, KEP-5958 — the model says
so in an attribute and the ground truth classifies the answer **ambiguous**.

**`Q-unsupported` returns empty**: every invariant carries a citation.

### The sharpest limitation is granularity, not expressiveness

`Q-tests` answers *which file*, because the model has one node for a file of 30
test functions. Nothing about the query language or the metamodel caused that —
**the charter chose file granularity and the cost is now measurable.**

That is the most useful thing the milestone found about how to model, as distinct
from what Engineering OS can do.

### The predicted path-selection question did not arise

`ADR-0088` warned that retaining the best deterministic path is not the same as
preserving all valid explanations. **In this model it did not matter.** Every
multi-hop result reached its target by one materially distinct evidence path.
Recorded, not acted on.
