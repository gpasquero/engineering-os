# SESSION-0014 — 2026-08-02

## Objective

Record the owner's acceptance of `SESSION-0013`, resolve the layer assignment
problem, and record the general principle it generalizes into.

## Acceptance recorded

**`ACCEPT-0009`** — the Project Owner accepted the `SESSION-0013` decisions at
revision `dd3d26e`. Those revisions are now `Active`.

The rationale: the layering is **explicit and internally consistent**, and
separating Layer A from Layer B establishes a clean semantic foundation for
every future adopting repository.

## Decisions made

**`ADR-0039` — layers classify artifacts, not directories.** A directory may
contain artifacts of several layers. Repository layout is an implementation
concern; the semantic layer is an architectural one. **The compiler classifies
artifacts, not folders.** Governance, tooling, automation, validation, testing
and CI/CD are **Cross-Cutting Infrastructure**, orthogonal to the semantic
layers. Resolves `ISSUE-0056`.

**`ADR-0040` — Architectural Dimensions.** Artifacts are classified along
multiple independent axes simultaneously — Semantic Layer, Artifact Taxonomy,
Lifecycle, Governance Status, Ownership, Authority, Visibility, Compilation
Phase — rather than being forced into a single hierarchy. The metamodel models
dimensions explicitly.

## What was learned

**All four readings recorded in `ISSUE-0056` were wrong, because the question
was.** The issue asked which layer owns `shared/`, `skills/`, `workflows/` and
`governance/`, and offered four ways to answer it. The answer is that the
question assigns layers to *directories*, and layers own *semantic artifacts*.

That is the second time in three sessions that an issue's own candidate answers
were all rejected in favour of reframing — `ISSUE-0053` was the first. Both
times the issue had converged on a plausible mechanism while the defect was in
how the problem was posed.

**`ADR-0040` is the general form of a fix applied five times locally.** Every
previous vocabulary collision — "skill", "authoritative", "state", "policy",
"registry" — was resolved by splitting an overloaded term. Dimensions name *why*
the terms became overloaded: one classification was being asked to do several
jobs. Each split was a local remedy; this is the structural one.

**`ADR-0038`'s four questions turn out to be a projection of the dimension
set.** Which layer, authoritative or derived, and which compiler phase are values
along Semantic Layer, Artifact Taxonomy and Compilation Phase. The questions were
an early partial view of something larger, written two sessions before the thing
they were a view of.

**The most-read structural document was demoted.** `repository-architecture.md`
is organised around directory contracts, and those are now implementation
guidance rather than architecture. A banner was added saying so, because
otherwise it will keep being read as normative.

**Everything this repository currently contains is cross-cutting.** Outside
`imports/` and `sources/`, every artifact is governance. Fourteen sessions in,
the project has produced no semantic artifact at all — no Layer A, B, C or D
content. That is not a defect; it is what building the governance layer first
means. But it is worth stating plainly in the build state, which now does.

**A collision appeared inside the ADR that exists to prevent collisions.**
`ADR-0040` lists `Governance Status` and `Lifecycle` as separate dimensions.
`ArtifactRevisionLifecycle` already has `Draft`, `Under Review`, `Accepted`,
`Active`, `Superseded`, `Archived` — which is governance status by another name.
`Ownership` and `Authority` may likewise be one axis; the worked example gives an
`Owner` value and no `Authority` value at all. Recorded in `ISSUE-0057`.

**Dimensions are an extensible concept, which triggers an existing obligation.**
`ADR-0031` requires every extensible concept to be evaluated for
Registry + Specification modeling, and `ADR-0027` answered the analogous question
for state machines with registration rather than enumeration. So whether
dimensions are registered is not an open preference — it is a compliance
obligation the project created for itself.
