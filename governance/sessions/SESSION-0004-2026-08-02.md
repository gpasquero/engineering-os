# SESSION-0004 — 2026-08-02

## Objective

Record the owner's answers to the four issues opened by the knowledge-compiler
decisions, and propagate their consequences. Both M2 blockers were among them.

## Decisions made

**`ADR-0014` — knowledge compiler over a three-tier knowledge model.**
Supersedes `ADR-0011`. Repository assets are authoritative; the canonical
knowledge model is derived. Three tiers named explicitly: Authoritative
Knowledge Model (`model/`, `governance/`), Canonical Knowledge Model (compiler
internal representation, never hand-edited, never inside `model/`), Derived
Artifacts. Resolves `ISSUE-0034`.

**`ADR-0015` — authoring is non-deterministic; compilation is deterministic.**
AI agents are authors exactly like human engineers. An authored artifact becomes
authoritative only after human acceptance and version control. No fifth artifact
category. Resolves `ISSUE-0033`.

**`ADR-0016` — governance is authoritative; manifests are projections.**
`BUILD-STATE.yaml` is generated from governance documents, not maintained beside
them. Hand-maintenance is permitted only as explicitly tracked transitional
debt. Resolves `ISSUE-0035` and `ISSUE-0028`.

**`ADR-0017` — reference architecture, not reference implementation.** The
architecture depends on no implementation language; the compiler exposes a
stable interface. An adopting repository does not need the toolchain to consume
Engineering OS, and authoritative artifacts must remain human-readable without
executing the compiler. Language deferred. Resolves `ISSUE-0032`.

## What was learned

**Third supersession, and the mechanism has now handled three distinct cases.**
`ADR-0006`→`ADR-0010` corrected a wrong claim. `ADR-0009`→`ADR-0013` narrowed a
scope with nothing wrong. `ADR-0011`→`ADR-0014` added a distinction that had
been missing. All three used the same mechanism with no special treatment, and
in every case the superseded belief remains readable.

**Two issues turned out to be one problem.** `ISSUE-0028` (hand-maintained issue
index) and `ISSUE-0035` (`BUILD-STATE.yaml` duplicating governance) are the same
failure at different scales: a derived artifact authored by hand. `ADR-0016`
resolves both with one decision. Worth noting for the future — issues recorded
separately because they were *discovered* separately may share a single cause.

**`ADR-0015` promoted a methodological question into an architectural one.**
Making human acceptance the transition to authoritative status means the entire
three-tier model rests on acceptance being real. `ISSUE-0009` was raised to also
block M2 and its statement sharpened: beyond "who lifts a blocked gate", the
project must define what acceptance *is*. **Nothing currently prevents an agent
from committing its own output and self-certifying it as authoritative** — that
gap exists today, in this repository, in this session.

**`ADR-0017` reinforced `ADR-0001` structurally rather than rhetorically.** The
requirement that authoritative artifacts stay usable without the compiler means
the session protocol — reconstruct context by reading the repository — is
guaranteed to keep working forever, by architectural constraint rather than by
current circumstance.

**Deferring the language has a running cost, and it is now visible.** M2 loses
executable tooling, which moves to M9, which means every projection stays
hand-maintained for longer. Rather than leave that implicit, `ISSUE-0037` was
opened as a register of the debt, listing five hand-maintained projections. The
index files now carry a visible notice saying they are projections. The debt
grows with every record added, which is the strongest argument against deferring
`ISSUE-0036` indefinitely.

**The debt in `ISSUE-0037` produced a defect within minutes of being opened.**
The hand-written counts in `governance/issues/index.md` claimed 21 open and 15
resolved; the issue files said 22 and 14. The drift was caught by a validation
script comparing the index against front matter, and corrected.

This is not an anecdote — it is the argument. A projection maintained by hand
drifted from its source inside a single session, in a repository of 37 issues,
maintained by a party that had just written the ADR forbidding it. The register
in `ISSUE-0037` should be read as an active hazard, not a tidy-up task.

**`ISSUE-0029` got sharper without being answered.** The three tiers mean a
Knowledge Package must export exactly one of: the authoritative assets, the
canonical model, or a dedicated federation projection. The second or third is far
more likely than the first, but a package derived from the canonical model would
have a version depending on the compiler version as well as the content — which
is a real design problem for federation.
