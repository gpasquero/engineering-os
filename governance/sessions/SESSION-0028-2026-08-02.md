## Decisions made

**`ADR-0076` — the Canonical Knowledge Model is a Layer A entity.**

The direction to specify it appeared to contradict `ADR-0053`, which states the
metamodel contains no compiler concepts. Resolving it produced a general test:

> **A concept is a compiler concept only if it is meaningless without a
> compiler.**

The compiler does not invent the model. It **materialises** it — the meaning
exists in the sources whether or not anything reads them. `Compiler`,
`Compiler Phase`, `Projection` and `ValidationResult` all fail the test;
`CanonicalKnowledgeModel` passes.

**`ADR-0053` was not amended.** The boundary it drew was right; what was missing
was a stated criterion for which side a concept falls on.

**`ADR-0077` — the compiler executes ValidationRules; it does not contain them.**
Rule *kinds* are mechanisms and live in code; *rules* are data and live in the
model.

**`ADR-0078` — schema-validated parsing.** Real YAML, schemas, validated before
semantic resolution. A structural error is reported at Parsing and never reaches
Resolution.

**`ADR-0079` — the Explorer is the primary interface**, not a visualization.

## What was learned

### Declaring rules as data produced rules that writing conditionals had not

Five checks existed as Python. Seven exist as declarations.

`VR-0005` (no self-reference) and `VR-0006` (a `WorkflowStep` must declare
`executes`) were written because **a table invites the question *what else
belongs here?* in a way a function does not.**

Then `VR-0007` — *an `ArtifactRevision` must declare `revision-of`* — was written
by generalising `VR-0006`, without looking at any project. **It immediately
failed the `dimensions` fixture**, whose revision had declared no artifact since
the fixture was created two sessions ago.

A rule derived from another rule found a defect that three sessions of passing
tests had not.

### The phase boundary is now provable

`malformed-yaml` declares `relationships` as a string. Under the regex parser
that was **silently an empty list**, and the file compiled to a valid node with
no edges — a structural defect reinterpreted as a correct model.

It now fails at Parsing, and the fixture asserts the phase. `ADR-0078`'s
distinction is not a description of intent; it is checked.

### A stale bytecode cache produced a phantom failure

Verifying that golden-output tests detect emitter drift, the emitter was
temporarily changed from `graph LR` to `graph TD` and restored. The suite then
failed five fixtures against a source file that plainly said `LR`.

**`graph LR` and `graph TD` are the same length**, and the two writes fell in the
same second. Python's bytecode cache validates on `(mtime, size)`, so the
restored source was byte-different and cache-identical. macOS keeps the cache
outside the repository, so `find . -name __pycache__` found nothing.

Two consequences: `__pycache__` is now git-ignored, and the drift check was
re-run with an edit of a **different length**, which passes. **The golden tests
were right and the environment was lying** — worth recording because the first
instinct was to distrust the new code.

### The repository validator found a gap in the vocabulary

Writing the two new entity specifications used `represents`, `derives-from` and
`validates` — **core types, used directly**, which is exactly what `ADR-0071`
says a new entity should do.

The validator reported all three as unregistered predicates, because the mapping
table recorded only predicates that *specialize* a core type and never recorded
that **a core type is a predicate that is its own parent.**

The rule was right and the registry was incomplete. Caught by a check written
three sessions before the case existed.

### Semantic navigation exposes gaps before it exposes answers

`ADR-0079` predicted this and the provenance query demonstrates it immediately:
the model carries a source **path**, while `ADR-0064` defines identity as
`(artifact-id, revision-id)`. The Explorer states the gap rather than hiding it.

**Every query is a demand on the model.** *Show acceptance history* requires
acceptance to be in the model; *show impact* requires the graph to be traversable
in both directions. Both now are.

### The compiler enriches rather than only transforms

The Canonical Knowledge Model now carries the **relationship vocabulary** for
every core type its edges use, so the Explorer can answer *why does this
relationship exist?* from the model alone rather than by consulting the
metamodel. That is enrichment, and it is what makes the model self-describing.
