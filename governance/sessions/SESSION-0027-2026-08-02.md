## Decisions made

**`ADR-0072` — the semantic model is the product.**

> A validator answers *"is this repository correct?"*
> A compiler answers *"what knowledge exists in this repository?"*

The compiler is not validating documents. It is **constructing an executable
semantic model**, and that model is the primary product. OWL, the Explorer, the
graphs, every register and all future documentation are **projections of it**.

**`ADR-0073` — compiler phases are first-class.** Authoring → Discovery →
Parsing → Resolution → Canonical Knowledge Model → Projection. Every feature
declares **input phase, output phase, invariants, determinism guarantee**.
`--phases` prints the contract without reading the implementation.

**`ADR-0074` — `RelationshipType` is a type system.** Seven fields per predicate:
semantic definition, parent, domain, range, cardinality, and optionally inference
and validation rules. Optimize for semantic reuse, not for reducing predicates.

**`ADR-0075` — entities are justified by compiler need.** *If the compiler never
needs an entity, question whether the metamodel needs it either.*

## What was learned

### The distinction reclassifies `ISSUE-0037`

Under `ADR-0072`, a hand-maintained projection is **a projection with no model
behind it** — an architectural violation rather than an operational
inconvenience. Four governance indexes, the corrections table and the metamodel
ontology itself are all in that state.

The decision also settles what `FINDINGS.md` left open: **neither Markdown nor
OWL is authoritative.** Both are projections; Markdown is additionally the
authoring form.

And it states a cost honestly: **the declared product barely exists.** The
Canonical Knowledge Model covers thirteen example nodes and none of the 192
governance records.

### The suite found a defect in its own fixture on the first run

`relationship-taxonomy` declared that it exercised all four relationship
categories. It compiled, and the suite failed it:

```text
expected relationship category 'semantic', absent
```

`has-position` is a **datatype** property, not an edge. The project had
structural, behavioral and traceability edges and no semantic one.

**A suite that recorded actual output as expected output would have enshrined the
gap.** Declaring counts and categories in advance is what caught it, and that is
the argument for expectations being authored rather than captured.

### Negative fixtures carry more weight than positive ones

Four of ten projects must fail. **A compiler that accepts everything passes every
positive test**, so the negative fixtures are what prove the metamodel is an
executable contract rather than a description.

Each names the decision it defends. If `unregistered-predicate` ever compiles,
`ADR-0071` has become decoration.

### Determinism moved from claim to check

`ADR-0073` requires each feature to declare a determinism guarantee. The suite
compiles every passing project **twice** and compares the two Canonical Knowledge
Models. Two invariants had to be added to make that true — sorted edges and
sorted errors — which is a guarantee that did not exist before it was declared.

### `ADR-0075` produced a four-two split, not six-zero

Applying *what would the compiler do differently?* to the six remaining entities:

| Needed now | Needed soon | Deferred |
|---|---|---|
| `ValidationRule`, `Registry` | `Vocabulary`, `Manifest` | `Principle`, `KnowledgePackage` |

**That the split is four-two rather than six-zero is the evidence the decision
was worth making.** `Principle` and `KnowledgePackage` are not wrong — they are
early: the compiler compiles no ADRs, and there is one repository. They are
deferred with stated triggers rather than deleted.

**Two entities are already Python that the model should own.** `resolve()`
hard-codes the rule *every predicate declares a registered parent*, and the
compiler reads the relationship vocabulary out of Markdown with a regex. Those
are `ValidationRule` and `Registry` respectively, existing as implementation
because the model has no term for them yet.
