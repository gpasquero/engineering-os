## What was learned

### The change is real, and that mattered

`97ca033 feat: Etapa 3 — SLA business-hours` from `ai-desk`'s own history, with
the "before" state taken from a detached `git worktree` so the working tree was
never touched.

**A simulated change would have proved nothing.** The mechanical delta —
`suites +1`, one file, 11 cases — is what the repository actually did, and every
downstream number follows from it.

### Continuous Acquisition costs 1.3% of a rerun

**4 incremental proposals against 302.** That ratio is the whole argument for the
mode: *do not rerun the complete onboarding workflow after every change.*

`D-missed-incremental-update: 0` — nothing the reacquisition found in the changed
evidence was absent from the maintained model.

### The drift report found a defect on its first real run — and not the one it was for

**`D-unsupported-assertion: 1`.** `Invariant.Addbusinessminutes` is maintained
and a full reacquisition does not support it.

The suite declares **two** `describe` blocks. `Continuous`'s rule `C1` iterates
all of them; `R4` reads only `describes[0]`.

> **Two acquisition modes disagreed about the same evidence.**

This is not drift between the model and the repository. It is **drift between two
mechanisms that were supposed to agree**, and no other check in this repository
would have caught it: both modes are individually correct, deterministic and
reproducible.

**It is recorded and deliberately not fixed.** Correcting `R4` would remove the
finding and the evidence that the mechanism works. The divergence is now a
documented question; whichever rule is wrong, the correction is a proposal like
any other.

### The report states the size of a choice nobody was measuring

**72 of 299 proposals were authorized.** `D-implementation-without-knowledge: 123`
and `D-new-knowledge: 104` are the cost of that curation decision, and **nothing
previously reported it.**

A model can now say *how much of the system it does not describe*, which is a
different and more useful statement than *what it describes*.

### The architecture was ahead of the implementation, and that is worth noting

Three ADRs specified this lifecycle before any of it existed, and **building it
required no new decision.** Every mode, category and constraint was already
declared.

That is the first session in a long while where the correct outcome was to build
rather than to decide — and it is a signal that the architectural phase this
project has been in for several sessions has, for now, run its course.
