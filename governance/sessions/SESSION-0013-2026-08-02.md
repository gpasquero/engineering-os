# SESSION-0013 — 2026-08-02

## Objective

Record the owner's acceptance of `SESSION-0012`, resolve the metamodel's
location together with the self-model question, and record the resulting
four-layer architecture.

## Acceptance recorded

**`ACCEPT-0008`** — the Project Owner accepted the `SESSION-0012` decisions at
revision `2d35b74`. Those revisions are now `Active`.

The rationale endorses accepting a real cost: `ADR-0036` gated M2's readiest
deliverable on a metamodel that did not exist, and the reviewer names why that
trade is correct — **positioning the metamodel first preserves implementation
independence**, so future compilers conform to a shared semantic contract rather
than to an existing implementation.

## Decisions made

**`ADR-0037` — the four-layer semantic architecture.** Supersedes `ADR-0014`.
The Metamodel is **Layer A** and defines the language; Layer B is a repository's
knowledge model expressed in that language; Layer C is the compiler-generated
canonical model; Layer D is the derived projections. Every artifact belongs to
exactly one layer. The metamodel is authored at `model/metamodel/`, versioned
with Engineering OS, and **adopters never modify it — they instantiate it**.
Resolves `ISSUE-0055` **and** `ISSUE-0031`.

**`ADR-0038` — four questions for every new artifact type.** Which layer owns
it; authoritative or derived; what metamodel entity it instantiates; which
compiler phase consumes or produces it. **An unanswerable question is a
rejection, not a gap to fill later.** Becomes the first mandatory
`ModelingPolicy` in M3.

## What was learned

**Two issues resolved by one decision, as recommended.** `ISSUE-0055` and
`ISSUE-0031` were the same question from opposite ends — where the metamodel
lives, and what Engineering OS's own `model/` contains. The answer settles both:
`model/metamodel/`, and the metamodel *is* the core of the self-model, because
Engineering OS's domain is how systems are described.

**M11 shrank as a side effect.** The self-model was an open-ended milestone;
most of it is now delivered in M2 as the metamodel.

**The three tiers survived intact, renamed.** `ADR-0014`'s authoritative /
canonical / derived became layers B, C and D. Nothing was lost — Layer A was
added above them. This is the second time an ADR was superseded purely to add a
level rather than to correct one (`ADR-0011` → `ADR-0014` was the first).

**"Layer" was redefined, and that is a first.** The project has resolved five
terminology problems by *splitting* an overloaded term. This one **redefines
existing terms**: `ADR-0010`'s "Layer A = the methodology" now means "Layer A =
the Metamodel". A reader arriving at `ADR-0010` finds the old meaning, so the
correction is recorded in the ADR index — the third entry in a Corrections table
that still has no machine-readable backing (`ISSUE-0048`).

**`ADR-0038` is failed by the existing corpus on the day it was written.** Its
first question is "which layer owns it?", and `shared/`, `skills/`, `workflows/`,
`templates/`, `schemas/` and `governance/` have no layer — they were Layer A
under the old meaning. `ISSUE-0056` is that compliance debt, and it blocks M2
because every M2 contract must declare a layer.

The most likely reading is uncomfortable and worth stating: **the metamodel
lists `Skill`, `Workflow`, `Policy` and `Capability` as entities, so concrete
skills and workflows are *instances*, and instances live in Layer B.** That would
make Engineering OS's own methodology part of this repository's domain
knowledge — coherent, and not what anyone has said out loud.

**Layer A lives inside `model/`, which needs stating wherever it matters.**
`ADR-0010` framed `model/` as the repository-local knowledge model. For adopters
that still holds. For Engineering OS, `model/` contains Layer A content, because
its domain genuinely is the metamodel. The shorthand "`model/` is Layer B" is
now false for exactly one repository.
