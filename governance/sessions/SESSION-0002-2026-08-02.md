# SESSION-0002 — 2026-08-02

## Objective

Record the owner's answers to the two issues blocking M2, and propagate their
consequences through the repository.

## What was done

Two owner decisions were recorded as ADRs, and the resulting changes were
propagated to the architecture, glossary, roadmap, indexes, build state and
README.

## Decisions made

**`ADR-0009` — `MANIFEST.yaml` is the root composition manifest.** It describes
the architecture and composition of an Engineering OS project — the equivalent
of `package.json` or `Cargo.toml`, but for Engineering OS composition rather
than source-code dependencies. Explicitly not a dependency lock file,
package-manager manifest or distribution descriptor. Fifteen concerns, from
repository metadata to validation configuration. Governing property: everything
else in the repository is discoverable from it. Resolves `ISSUE-0003`.

**`ADR-0010` — knowledge is repository-local; environments federate.** Every
repository adopting Engineering OS owns its own `model/`. Knowledge is owned by
the repository that owns the domain. No central shared model. Multi-repository
environments federate through versioned Knowledge Packages. Resolves
`ISSUE-0004`.

## What was learned

**`ADR-0010` contradicted an accepted decision.** `ADR-0006` had asserted that
this repository "never contains a live `model/` directory". The owner's answer
states that Engineering OS itself has a `model/` describing the framework. This
was not a detail — it inverts the claim that distinguished this repository from
its targets.

`ADR-0006` is therefore **superseded by `ADR-0010`**, per the documentation
system: an accepted ADR is never edited, only superseded. Two of its three
claims survive — the Layer A / Layer B distinction, and `model-spec/` as the
specification of the tree. The corrected claim is that both layers coexist in
*every* adopting repository, including this one. What distinguishes this
repository is that it also **authors** Layer A.

This is the first supersession in the project, and it validated the mechanism:
the wrong belief is still readable at `ADR-0006`, the correction is traceable,
and nothing was silently edited.

**The methodology now applies to itself.** Dogfooding stopped being optional and
became a milestone. If Engineering OS cannot produce a coherent knowledge model
of itself, the methodology does not work — so M11 was inserted **before** the v1
release rather than after it. The former Delivery 10 moved from M11 to M12.

**`ADR-0009` effectively answers `ISSUE-0005` without deciding it.** The
manifest declares build pipelines, documentation generators and validation
configuration; `ADR-0009` further requires that manifest sections derivable from
the filesystem be generated or validated rather than hand-maintained. None of
that is achievable by specification alone. The issue was updated with this
evidence and raised from M9 to M2, but left open — it is an owner decision, and
inferring it would violate the rule against assuming.

**A new duplication risk was created deliberately.** A manifest with fifteen
concerns that must stay in sync with the filesystem is the `ISSUE-0028` drift
failure at a larger scale and with worse consequences. Recorded as a negative
consequence in `ADR-0009` with a requirement to generate or validate rather than
hand-maintain, to be settled in M2.

**`ADR-0010` simplified an open issue.** Because `model/` is always
repository-local and never configurable, `ISSUE-0015` narrows to the Layer A
side only — a skill referencing its own templates or a shared policy. The Layer
B root is fixed.

## Issues opened

- `ISSUE-0029` — Knowledge Package format and federation protocol undefined.
  Blocks M13, and constrains M2: nothing built there may preclude federation.
- `ISSUE-0030` — `MANIFEST.yaml` serves two audiences (this repository, which
  authors the methodology, and adopting repositories, which consume it).
  Whether one schema covers both is undefined. Blocks M2.
- `ISSUE-0031` — the scope of Engineering OS's own `model/` is undefined,
  including the unresolved overlap between `governance/` and `model/`. The
  glossary is already a Layer B artifact by any reasonable reading, yet it lives
  in `governance/` because it existed first.
