# SESSION-0015 — 2026-08-02

## Objective

Record the owner's acceptance of `SESSION-0014`, settle how dimensions are
defined and how artifacts are classified, and record the semantic separation
those two decisions imply.

## Acceptance recorded

**`ACCEPT-0010`** — the Project Owner accepted the `SESSION-0014` decisions at
revision `c8e50a2`. Those revisions are now `Active`.

The rationale names the shift: the architecture evolved **from a single
classification model into a multidimensional semantic model**, which removes the
need to overload concepts rather than relieving it case by case.

## Decisions made

**`ADR-0041` — dimensions are registered first-class entities.** A Dimension is
not merely a taxonomy; it is a semantic construct defining one independent axis
of classification, declaring eight required fields. A Dimension Registry
Specification is authoritative and its Projection generated. **Future dimensions
are added by registration, never by modifying compiler logic.** Resolves
`ISSUE-0057`.

**`ADR-0042` — Dimension Assignments.** Artifacts do not contain dimension
values. They are classified by explicit semantic relationships:
Artifact → Dimension Assignment → Dimension → Dimension Value. Assignments are
versioned, may change without changing artifact identity, and are what validation
targets. The Canonical Knowledge Model represents them as graph relationships
rather than embedded metadata. Resolves `ISSUE-0058`.

**`ADR-0043` — three semantic levels.** Metamodel defines entity *types*; Model
defines *instances*; Classification defines *semantic assertions about
instances*. This prevents classification systems from becoming part of the
object model itself, and the Knowledge Graph represents the three as distinct
node types.

## What was learned

**"Never by modifying compiler logic" is the strongest form of the Registry
Pattern so far.** Earlier instances constrained where data lives. This one
constrains the *implementation*, so extensibility becomes a property the
compiler cannot quietly withdraw.

It is also the **fifth** instance, and the first adopted because `ADR-0031`
obliged it rather than because the shape was noticed again. The pattern has
started doing work as a rule rather than as an observation.

**Third reframing in three sessions.** `ISSUE-0058` offered four options for how
an artifact declares its classification, and all four were rejected — each
treated classification as a *property of the artifact*. After `ISSUE-0053` and
`ISSUE-0056`, this is the third time an issue converged on a plausible mechanism
while the defect was in the framing.

The pattern is worth naming: **when an issue's options all share an assumption,
the assumption is the issue.**

**`ADR-0043` explains three decisions that were made separately.** `Dimension` is
a Level 1 entity type, a registered dimension is a Level 2 instance, and an
assignment is a Level 3 classification. Each was decided on its own merits; the
levels show they were one design.

**A near-collision arrived in the ADR that establishes the separation.** `Level`
and `Layer` are now two ordinal schemes, and **both begin with the metamodel**.
They are genuinely different axes — levels classify what kind of *statement*,
layers classify position in the *pipeline* — but the coincidence invites
conflation.

This is different from the six earlier terminology problems, which were one term
with two meanings, resolved by splitting. Here it is two terms for two different
things at risk of being read as one. Recorded as `ISSUE-0061` **before** it
propagated, which is the discipline `ADR-0035` established.

**A contradiction appeared between two decisions made minutes apart.**
`ADR-0040` states dimensions are independent — *a value on one never implies a
value on another*. `ADR-0041` requires each to declare *relationships to other
dimensions*. Both cannot be read strictly. `ISSUE-0059`.

**`ADR-0042` collides with `ADR-0017`, and this is the sharpest open problem.**
If classification exists only as relationships in the compiled graph, a human
reading an authoritative artifact **cannot tell what layer it belongs to, whether
it is authoritative, or who owns it** without running the compiler. `ADR-0017`
guarantees authoritative artifacts stay usable without the toolchain, and
`ADR-0001` requires the repository to be legible as memory.

The crux, recorded in `ISSUE-0060`: **is front matter a property, or a
serialization of a relationship?** If the latter, most of the tension dissolves.
